# 内存 · 磁盘 · 多级访存 · DMA —— 实测演示项目

一个可直接编译运行的 C++17 项目，用 **三个可重复的实验** 把计算机存储体系里最容易混淆的四组概念一次性实测清楚：

| 概念 | 实验 | 测什么 |
|---|---|---|
| **多级访存**（Cache Hierarchy） | 实验1 | L1 / L2 / L3 缓存与主存的随机访问延迟阶梯 |
| **内存 vs 磁盘** | 实验2 | 内存与磁盘的顺序带宽、随机访问延迟（数量级对比） |
| **DMA**（直接内存访问） | 实验3 | CPU 亲自搬运（PIO） vs 硬件搬运并行，CPU 时间节省 |

> 设计初衷：教科书上的"快几个数量级"很容易被忘记，亲手量出来的数字不会。

## 实验1：多级访存 —— 为什么有 L1/L2/L3

### 原理

CPU 直接访问主存（DRAM）太慢了（几十 ns），于是 CPU 内部集成了 **SRAM 做缓存**：离核越近越快、但越贵越小，逐级放大容量，形成"金字塔"：

```
寄存器 ──→ L1 ──→ L2 ──→ L3 ──→ 主存(DRAM) ──→ 磁盘(SSD/HDD)
   ~0.3ns   ~1ns    ~4ns    ~15-40ns   ~60-100ns    µs ~ ms 级
   最小      32-64KB  256KB-1.25MB  4-64MB    8-128GB     数百GB~数TB
```

缓存的意义建立在**程序局部性**上：
- **时间局部性**：刚访问过的数据大概率马上再访问；
- **空间局部性**：访问了一个字节，附近的数据大概率也要用（所以缓存按 **64B 缓存行** 整行搬运）。

当程序的数据集超过某一级缓存的容量时，这一级开始频繁**未命中（miss）**，请求下沉到下一级，延迟随之跳升——这就是实验测到的"阶梯"。

### 测量方法：指针追逐（Pointer Chasing）

随机访问最容易暴露缓存容量边界。代码把数组构造成一条**随机排列的链表**，每次访问都跳到数组里完全随机的下标：

```cpp
idx = next[idx];   // 每次访问随机位置，硬件预取器无法预测
```

这样测到的就是"随机访问 + 缓存未命中"的真实延迟，且不受硬件预取器的干扰。

### 本机实测结果（示例运行）

```
数组大小      单次访问延迟    预期所在层级
4.0 KB            2.72 ns    L1 内(命中率高)
32.0 KB           2.51 ns    L1 内(命中率高)      ← L1=32KB，超了就开始跳
64.0 KB           3.43 ns    L2 内(命中率高)
256.0 KB          5.18 ns    L2 内(命中率高)      ← L2=256KB
512.0 KB          9.82 ns    L3 内(命中率高)
16.0 MB          63.24 ns    L3 内(命中率高)      ← L3=16MB
32.0 MB          56.99 ns    超出最后一级缓存 → 主存
256.0 MB         84.10 ns    主存 + TLB 抖动
```

可以看到清晰的台阶：**2.5 → 5 → 10 → 60 → 84 ns**，与 CPU 的 L1/L2/L3/DRAM 容量一一对应（程序开头会打印检测到的缓存容量，方便对照）。256MB 档还叠加了 **TLB 抖动**——大数组的页面数超过 CPU 的 TLB（页表缓存），每次访问都要多走一次页表遍历。

## 实验2：内存 vs 磁盘 —— 两个数量级的鸿沟

### 原理

- **内存（DRAM）**：电容存储，纳秒级访问，GB/s 级带宽，断电丢失；
- **磁盘**：SSD 靠闪存单元（µs 级寻址），HDD 靠磁头机械寻道（ms 级），顺序读写快、随机读写慢。

关键差异不只是"快慢"，而是**随机访问成本**：内存随机访问和顺序访问几乎同价，而磁盘随机访问要比顺序慢几个数量级（HDD 尤其如此，因为磁头要物理移动）。

### 测量方法

- **内存**：`memset` 测顺序写、逐缓存行累加测顺序读、`memcpy` 测拷贝（双向流量）；随机延迟复用指针追逐法。
- **磁盘**：写一个临时大文件（默认 512MB），**写穿落盘**（Windows `_commit` / POSIX `fsync`）；读侧在 Windows 使用 **`FILE_FLAG_NO_BUFFERING` 无缓冲 IO**，绕开 OS 页缓存，直接打物理磁盘，保证测的是真实磁盘而不是内存缓存。

### 本机实测结果（示例运行）

```
── 内存 (512.0 MB) ──────────────────────────────────
  顺序写带宽            25.31 GB/s
  顺序读带宽            14.63 GB/s
  拷贝带宽(读+写)       21.98 GB/s
  随机访问延迟          81.78 ns

── 磁盘文件 (512.0 MB, 用完即删) ───────────────────
  顺序写带宽             0.74 GB/s   (含落盘)
  顺序读带宽             1.21 GB/s   (无缓冲, 绕开页缓存)
  随机读延迟           102.47 µs     (无缓冲随机读)

数量级对比：内存随机访问比磁盘随机读快约 1253 倍
```

数字自己会说话：
- **带宽**：内存 14~25 GB/s，磁盘 0.7~1.2 GB/s，差 **~20 倍**；
- **随机延迟**：内存 81.78 **ns**，磁盘 102.47 **µs**，差 **~1253 倍**。

> 磁盘数字取决于你的存储类型：NVMe SSD 顺序读通常 2~7 GB/s、随机读 20~100µs；机械硬盘顺序 100~250 MB/s、随机 5~15ms。本机测试结果显示这是一块 SATA 级 SSD（或写入策略保守的盘）。

## 实验3：DMA —— 谁在搬运数据？

### 原理

早期（或简单设备）用 **PIO（Programmed I/O）**：CPU 亲自把设备数据一个字节一个字节地搬进内存。搬运期间 CPU 被完全占用——设备越慢，CPU 越是被"绑死"。

**DMA（Direct Memory Access）** 的解决思路：让 CPU 只负责**下命令**，由专门的 **DMA 控制器**（可以是设备内置的，也可以是主板上的）接管数据搬运：

```
无 DMA (PIO)：     CPU ──搬运──▶ CPU ──计算──▶       总耗时 = 搬运 + 计算（串行）

有 DMA：           CPU ──发起──▶ CPU ──计算──▶       总耗时 ≈ max(搬运, 计算)
                               └─ DMA控制器 ──搬运──▶ (完成后发中断通知 CPU)
```

搬运期间 CPU 可以并行执行其他任务，DMA 完成后通过**中断**通知 CPU"数据已就绪"。磁盘、网卡、显卡、声卡全部依赖 DMA——没有它，千兆网卡就能把 CPU 占满。

### 模拟方式

用户态无法直接操作真实 DMA 控制器，本项目用**后台线程模拟 DMA 引擎**：
- PIO 模式：`memcpy` 和计算在 CPU 上**串行**执行；
- DMA 模式：`memcpy` 交给后台线程（模拟 DMA 引擎），主线程立刻开始计算，`future.wait()` 模拟"传输完成中断"。
- 计算任务特意选 **CPU 密集型**（xorshift 依赖链，几乎不占内存带宽），保证计算与搬运能真正并行、对比公平。

### 本机实测结果（示例运行）

```
[无 DMA（PIO 模式）—— CPU 亲自搬运]
  阶段1 搬运数据 .....    49.75 ms
  阶段2 执行计算 .....    54.04 ms
  总耗时 .............   103.79 ms   (CPU 全程忙碌)

[有 DMA —— CPU 发起传输后立即返回]
  CPU 并行执行计算 ...    54.00 ms
  总耗时 .............    54.00 ms   (CPU 几乎零等待)

对比：DMA 模式节省 49.79 ms（48.0%）
```

DMA 模式总耗时 ≈ max(搬运, 计算)，与理论一致。数据量越大、设备越慢，DMA 的价值越显著——这也是为什么任何高速外设都离不开 DMA。

## 概念对照总表

| 层级 | 典型容量 | 典型延迟 | 典型带宽 | 介质/实现 | 断电丢失? | 谁管理 |
|---|---|---|---|---|---|---|
| 寄存器 | 64~256 B | ~0.3 ns | 数 TB/s | SRAM（CPU 内） | 是 | 编译器/CPU |
| L1 缓存 | 32~64 KB | ~1 ns | 1~2 TB/s | SRAM（核内） | 是 | 硬件 |
| L2 缓存 | 256KB~1.25MB | ~3~8 ns | 数百 GB/s | SRAM（核内/核间） | 是 | 硬件 |
| L3 缓存 | 4~64 MB | ~10~40 ns | 100~300 GB/s | SRAM（多核共享） | 是 | 硬件 |
| 主存 DRAM | 8~128 GB | ~60~100 ns | 20~60 GB/s | DRAM | 是 | OS + MMU |
| NVMe SSD | 256GB~8TB | 20~100 µs | 1~7 GB/s | NAND Flash | 否 | 设备 + 驱动 |
| HDD | 1~20 TB | 5~15 ms | 100~250 MB/s | 磁介质 | 否 | 设备 + 驱动 |

> 数值为典型量级，具体以你的硬件规格为准。**DMA** 是"数据如何从设备到内存"的搬运机制（贯穿磁盘/网络/显卡），与"内存/磁盘/缓存"这些存储介质正交——实验3演示的正是它。

## 常见问题

**Q1：为什么 4KB 数组的延迟是 2.5ns 而不是理论 ~1ns？**
指针追逐每跳还有地址计算、volatile 读、循环开销，且随机访问一个缓存行只用了 4B，利用率低。但各档之间的**相对台阶**才是关键，不受这些常量影响。

**Q2：为什么内存顺序读比写慢？**
写用 `memset`（编译器/库做了 SIMD 宽写，无依赖）；读用 volatile 逐缓存行累加，编译器不能向量化合并，形成访存依赖链，效率天然低一截。数值随编译器优化策略波动，不影响结论。

**Q3：磁盘读为什么要"无缓冲"？**
普通 `fread` 读刚写完的文件，OS 页缓存直接命中，测的是内存速度（本机曾测出 5.57 GB/s 和 0.00µs 随机延迟）。`FILE_FLAG_NO_BUFFERING` 强制从物理磁盘读，才是磁盘的真实水平。

**Q4：DMA 实验是真 DMA 吗？**
不是，是教学模拟（用户态碰不到硬件 DMA 控制器）。但它精确复现了 DMA 的结构：发起后 CPU 不参与搬运、传输与计算并行、完成后有"中断"通知。真实场景中 DMA 描述符由驱动配置、由硬件执行。

**Q5：为什么内存带宽只测出十几 GB/s 而不是主板标称的几十 GB/s？**
单线程顺序访问通常跑不满多通道带宽（需要多线程+非临时指令）。本项目目标是展示**数量级差异**，单线程数据已足够说明问题。
